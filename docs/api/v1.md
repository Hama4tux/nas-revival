# Administration API v1

Status: implemented as a read-only prototype (M4), 2026-11-25. Served by the `nas-revival`
Go binary together with the static UI. All paths are below `/api/v1`. JSON only, UTF-8.

## Conventions

- Authentication: session cookie `nr_session` (`HttpOnly`, `Secure`, `SameSite=Strict`, path `/`),
  idle timeout 30 min, absolute 12 h. Every endpoint except `POST /session` needs it; otherwise `401`.
- CSRF: every non-GET request must carry `X-Requested-With: nas-revival`; otherwise `403`.
- Errors: `{"error": {"code": "<machine_code>", "message": "<human text>"}}`. No stack traces.
- Missing data is `null`, never `0`. Byte values are integers in bytes, temperatures in milli-°C.
- Timestamps are RFC 3339 UTC strings.

## Endpoints

### `POST /session`
Body `{"username": "admin", "password": "..."}`. `204` + cookie on success, `401 invalid_credentials`,
`429 rate_limited` (5 failed attempts per client IP within 5 min; `Retry-After` header in seconds).

### `GET /session`
`200 {"username": "admin", "expiresAt": "2026-11-25T18:00:00Z"}` or `401`.

### `DELETE /session`
`204`, cookie cleared.

### `GET /overview`
Poll every 5 s while the page is visible. Served from the shared collector (MON-01): one goroutine
collects every 5 s while somebody asked in the last 30 s, otherwise every 60 s; all clients get the
same snapshot. A request after an idle period wakes the collector and waits up to 3 s for a fresh one.

```json
{
  "generatedAt": "2026-11-25T16:00:00Z",
  "host": {"hostname": "nas", "os": "Debian GNU/Linux 13 (trixie)", "kernel": "6.12.119",
           "uptimeSeconds": 12345, "boardModel": "ZyXEL NSA310"},
  "cpu": {"model": "Feroceon 88FR131 rev 1 (v5l)", "cores": 1,
          "load1": 0.12, "load5": 0.10, "load15": 0.05, "usagePercent": 3.5},
  "memory": {"totalBytes": 262144000, "availableBytes": 180000000,
             "swapTotalBytes": 1073741824, "swapFreeBytes": 1073741824},
  "sensors": {"status": "ok",
              "temperatures": [{"id": "lm85/temp1", "label": "temp1", "milliCelsius": 41000}],
              "fans": [{"id": "lm85/fan1", "label": "fan1", "rpm": 1800}]},
  "network": [{"name": "eth0", "up": true, "speedMbps": 1000,
               "rxBytes": 123, "txBytes": 456, "addresses": ["192.0.2.10/24"]}],
  "storage": {
    "disks": [{"name": "sda", "model": "ST1000LM014", "sizeBytes": 1000204886016,
               "rotational": true, "removable": false, "powerState": "active"}],
    "filesystems": [{"mount": "/srv/data", "device": "/dev/sda3", "fsType": "ext4",
                     "totalBytes": 1, "usedBytes": 1, "availableBytes": 1}]
  },
  "services": [{"name": "ssh.service", "label": "SSH", "state": "active", "since": "2026-11-25T15:10:00Z"}],
  "health": {"status": "warn", "checkedAt": "2026-11-25T16:00:00Z", "smartCheckedAt": "2026-11-25T15:55:00Z",
             "problems": [{"severity": "warn", "code": "fsWarn", "subject": "/media/usb"}]}
}
```

- `health.status`: `ok | warn | crit | unknown`, the worst problem wins. `unknown` means the last
  collection failed: the snapshot is the last good one and `problems` starts with `collectFailed`.
- `health.problems[]`: crit first. `severity` `warn | crit`; `subject` names the disk, mount, service or
  fan when there is one. Codes: `sensorsFault` (crit), `sensorsUnknown`, `fanStopped` (rpm 0),
  `smartFailed` (crit), `smartSectors` (reallocated or pending > 0), `fsCritical` (> 95 %, crit),
  `fsWarn` (> 85 %), `serviceFailed` (crit), `collectFailed`. Sleeping disks are not judged by SMART.
- `health.checkedAt` is when the snapshot was evaluated; `smartCheckedAt` when the SMART data behind it
  was read (cached 10 min, `smartctl -n standby`), `null` without SMART.
- `disks[].powerState`: `active | standby | sleeping | unknown` from `hdparm -C` (never wakes the drive),
  asked at most once a minute per disk; `null` for removable disks (USB bridges answer with garbage).

- `cpu.usagePercent` is `null` on the first sample after start (needs two `/proc/stat` samples).
- `sensors.status`: `ok | unknown | unsupported | fault`. Sensors come from hwmon, matched by driver
  name, never by a fixed hwmon index. A board profile (by device-tree model) may list the wired
  fans; then only those are reported, with a friendly label (NSA310: one fan, `lm85/fan1`).
- `network[].speedMbps` is `null` when the link is down or unknown.
- `filesystems` lists only real block-device mounts (no tmpfs/proc/cgroup).
- `services[].state`: `active | inactive | failed | done | unknown`; only an allowlist of units is reported.
  `done` is a oneshot unit that ran and exited successfully (e.g. LED setup at boot).
- `services[].since`: when the unit last changed its active state (systemd `StateChangeTimestamp`), or `null`.
  The UI derives "Poslední události" from it plus the boot time (`generatedAt − uptimeSeconds`).
- `filesystems[].device`: the kernel alias `/dev/root` is resolved to the real partition (via mountinfo and
  `/sys/dev/block`), so volumes can be matched to disks.

### `GET /smart`
SMART summary; cached for 10 min, disks in standby are not woken (`smartctl -n standby`).

```json
{
  "checkedAt": "2026-11-25T16:00:00Z",
  "disks": [{"name": "sda", "model": "ST1000LM014", "health": "passed",
             "temperatureCelsius": 38, "powerOnHours": 1200,
             "reallocatedSectors": 0, "pendingSectors": 0, "standby": false}]
}
```

- `health`: `passed | failed | unknown`. `standby: true` means values were not read.
- If `smartctl` is unavailable the response is `200` with `"disks": []` and `"error": "smartctl_unavailable"`.

### `GET /system/info`
Rarely changing identification. Missing values are `null`.

```json
{"version": "8fd3825", "hostname": "nas", "boardModel": "ZyXEL NSA310",
 "os": "Debian GNU/Linux 13 (trixie)", "debianVersion": "13.8", "kernel": "6.12.119",
 "architecture": "armv5tel", "cpuModel": "Feroceon 88FR131 rev 1 (v5l)", "cores": 1,
 "memTotalBytes": 252043264, "bootTime": "2026-11-25T15:37:00Z", "uptimeSeconds": 10800,
 "lastPackageChange": "2026-11-25T18:55:00Z"}
```

`version` is `git describe` of the build; `lastPackageChange` is the last dpkg activity.

### `POST /system/{reboot,shutdown}/preview`
Preflight for a restart or shutdown (CORE-12, CORE-13). Runs `power.preflight` in the helper, which
never wakes a sleeping disk, and issues a confirmation token (60 s, single use, bound to user and action).

```json
{"action": "reboot", "hostname": "nsa310", "confirmToken": "…", "expiresAt": "2026-11-25T20:00:00Z",
 "effects": ["web_offline", "connections_drop", "sessions_end", "back_in_minutes"],
 "blockers": [{"code": "smart_test", "diskId": "wwn-0x…"}]}
```

Effects: `web_offline`, `connections_drop`, `sessions_end`, `back_in_minutes` (reboot), `power_button`
(shutdown). Blockers: `smart_test` (with `diskId`), `copy_running` (COPY button backup), `package_manager`
(apt/dpkg process), `network_pending` (network change waiting for confirmation), `check_failed`
(a check could not run). The UI asks the user to type `hostname`.

### `POST /system/{reboot,shutdown}`
Body `{"confirmToken": "…", "force": false}`. The helper repeats the preflight; with blockers it refuses
unless `force` is true. On success it calls `sync`, answers `202 {"action", "forced", "blockers"}` and runs
`systemctl reboot` / `systemctl poweroff` 2 s later. Errors: `409 confirm_required` (token missing,
expired, used or for another action), `409 blocked`, `409 power_pending` (already on its way), `503`.

### `GET /system/capabilities`
Device profile (selected by device-tree `compatible`, fallback generic ARM / generic Linux) and the
evidence level of every hardware capability: `verified` (writes may be offered), `unverified`
(show, never write), `unsupported` (hide). IDs: `temperatures`, `fanSpeed`, `fanControl`, `leds`,
`copyButton`, `smart`, `diskStandby`, `kernelSlots`, `rtcWake`, `wakeOnLan`, `autoPowerOn`, `raid`.

```json
{"profileId": "zyxel-nsa310", "profileName": "ZyXEL NSA310", "sataBays": 1, "usbPorts": 2,
 "capabilities": [{"id": "fanControl", "status": "verified"}, {"id": "wakeOnLan", "status": "unverified"}]}
```

### `GET /storage`
Disks, partitions and mounts, read from sysfs, the udev database (`/run/udev/data`) and
`/proc/self/mountinfo` only, so the request never wakes a sleeping disk. `id` is the most stable
`/dev/disk/by-id` name (`wwn-…`, then `ata-…`/`nvme-…`/`usb-…`); `idStable: false` means udev had
no identity and `dev-<kernel name>` is used. `name` (`sda`) is informational and may change.
`type`: `hdd`, `sshd`, `ssd`, `flash`, `unknown`; `bus`: `ata`, `usb`, `nvme`, `mmc`, `unknown`.
`roles` (`system` = `/`, `boot` = `/boot`, `swap`, `data` = under `/srv`) come from the mounts;
`system` is true for a disk holding root or swap and `sharedWithData` when such a disk also holds
data (it cannot sleep). A filesystem on the whole disk appears as one partition named like the
disk. Mounts: the first mount of a filesystem counts its space (`usage`), every further one
(bind mount, subdirectory, duplicate) has `bind: true`. `readOnly` is the filesystem (superblock)
state; the service's own `ProtectSystem=strict` view is ignored. `serial` will be limited to
admins when roles arrive (W2.2).

```json
{"disks": [{"id": "wwn-0x5000c500…", "idStable": true, "name": "sda", "model": "ST1000LM014-SSHD",
  "vendor": null, "serial": "…", "firmware": "LVD4", "bus": "ata", "type": "sshd", "rotationRpm": 5400,
  "sizeBytes": 1000204886016, "removable": false, "smart": true, "readOnly": false, "partitionTable": "gpt",
  "system": true, "roles": ["system", "swap", "data"], "sharedWithData": true,
  "partitions": [{"name": "sda3", "number": 3, "sizeBytes": 966917824000, "partUuid": "…",
    "partLabel": "nas-data", "fsType": "ext4", "fsUuid": "…", "label": "nasdata", "swap": false,
    "mounts": [{"point": "/srv/data", "readOnly": false, "bind": false, "root": "/"}],
    "usage": {"totalBytes": 965637468160, "usedBytes": 2129920, "availableBytes": 965618561024}}]}]}
```

`smart` is true for internal SATA disks, the only ones that offer SMART detail and self-tests.

### `GET /storage/disks/{id}/smart`
SMART detail of one disk (W1.4, SMART-10/11). `{id}` is the stable disk ID from `GET /storage`.
Read with `smartctl -j -n standby -a`, so a sleeping disk is not woken: it answers `"standby": true`
with empty lists. Cached for 5 s (the UI polls every 30 s while a self-test runs). `404 disk_not_found`
for an unknown ID, `404 smart_unsupported` for a disk without `smart`.

```json
{"checkedAt": "2026-11-25T19:23:50Z", "standby": false, "health": "passed",
 "model": "ST1000LM014-SSHD-8GB", "family": "Seagate Laptop SSHD", "temperatureCelsius": 42,
 "powerOnHours": 6870, "powerCycles": 10115, "selfTestsSupported": true, "shortMinutes": 1, "longMinutes": 206,
 "selfTest": {"value": 249, "text": "in progress, 90% remaining", "running": true, "remainingPercent": 90, "passed": null},
 "attributes": [{"id": 7, "name": "Seek_Error_Rate", "value": 72, "worst": 60, "thresh": 30,
   "raw": "68992411861", "rawValue": 68992411861, "count": 16, "prefailure": true, "whenFailed": "",
   "key": false, "level": "ok"}],
 "history": [{"type": "short", "typeText": "Short offline", "status": "Completed without error",
   "passed": true, "remainingPercent": null, "lifetimeHours": 6865}]}
```

- `count` is the meaningful number after vendor decoding: temperature from the low byte (190, 194),
  hours from the low 32 bits (9), and on Seagate the error count from the upper 16 bits (1, 7, 195)
  and the sum of the three timeout counters (188).
- `level`: `crit` (below threshold, failing now, or reallocated/pending/uncorrectable/spin-retry > 0,
  temperature ≥ 60 °C), `warn` (timeouts or CRC errors > 0, ≥ 50 °C, load cycles ≥ 300 000, failed in
  the past), `info` (key attribute without a problem), `ok`. `key` marks 4, 5, 9, 10, 12, 187, 188,
  193, 194, 197, 198, 199.
- `history` is the drive's own self-test log (bounded by the drive, at most 21 entries, newest first);
  NAS Revival keeps no separate history file.
- `error`: `smartctl_unavailable` or `smartctl_failed` with empty lists.

### `POST /storage/disks/{id}/smart/test`
Starts a self-test through helper op `smart.test`. Body `{"type": "short" | "long"}` (unknown fields
rejected). Answers `202 {"diskId": "…", "type": "short", "estimatedMinutes": 1}`. Starting wakes a
sleeping disk. Errors: `400 invalid` (type), `404` as above, `409 test_running` (one test per disk;
the helper checks `smartctl -c` before `smartctl -t`), `503 helper_unavailable`. The helper resolves
the ID itself from sysfs/udev, accepts internal SATA disks only and logs every start.

### `GET /storage/disks/{id}/power`
Power state and settings of an internal SATA disk (PWR-01, PWR-02). The state comes from `hdparm -C`,
which never wakes the disk; APM (`hdparm -B`) is read only while the disk is awake, otherwise the
last value read is repeated.

```json
{
  "diskId": "wwn-0x…", "systemDisk": true, "state": "active", "checkedAt": "2026-11-25T20:30:00+01:00",
  "apmSupported": true, "apmLevel": 254,
  "settings": {"profile": "balanced", "standbyMinutes": 0, "apm": 254}, "stored": false,
  "profiles": [{"profile": "performance", "standbyMinutes": 0, "apm": 254},
               {"profile": "balanced", "standbyMinutes": 0, "apm": 254},
               {"profile": "eco", "standbyMinutes": 20, "apm": 128}],
  "standbyChoices": [0, 10, 20, 30, 60, 120, 180, 240, 300]
}
```

`state` is `active`, `standby`, `sleeping` or `unknown`. `stored: false` means the disk runs on the
default profile (balanced; it never spins down the system disk). `profiles` are the fixed profiles
as they apply to this disk. Errors: `404 disk_not_found`, `404 power_unsupported` (USB and other
disks hdparm does not address directly), `500 config_unreadable`.

### `PUT /storage/disks/{id}/power`
Body `{"profile": "performance" | "balanced" | "eco" | "custom", "standbyMinutes": 0, "apm": 254 | null,
"confirmSystemDisk": false}`; `standbyMinutes` and `apm` count only for `custom` (`apm` 1–255,
`null` leaves the drive's setting). Goes through helper op `disk.setPower`, which applies
`hdparm -B` (when the drive has APM) and `hdparm -S`, and stores the settings in
`/etc/nas-revival/disks.json` only after the drive accepted them; the helper applies the file at
every start (boot task `disk-power`). Answers `200` with the GET body. Errors: `400 invalid`
(profile, standbyMinutes, apm), `409 confirm_required` (standby timeout on the system disk without
`confirmSystemDisk: true`, ADR 0007), `503 helper_unavailable`.

### `POST /storage/disks/{id}/standby`
Spins the disk down now (PWR-03, helper op `disk.standby`, `hdparm -y`). Answers
`200 {"diskId": "…", "wasStandby": false}`; `wasStandby: true` means it already slept and nothing
was sent. Errors: `404` as above, `409 test_running` (a SMART self-test would be aborted),
`503 helper_unavailable`.

## Settings (write operations)

All write endpoints need the session and the CSRF header. Validation errors are
`400 {"error": {"code": "invalid", "message": "<Czech text>", "field": "<json field>"}}`.
The web process forwards network/time operations to the privileged helper (ADR 0003);
if the helper is not reachable: `503 helper_unavailable`.

### `GET /settings/network`

```json
{
  "interface": "enp1s0",
  "config": {"mode": "dhcp", "address": null, "prefixLength": null, "gateway": null,
             "dns": [], "useDhcpDns": true},
  "current": {"addresses": ["192.0.2.51/24"], "gateway": "192.0.2.1", "dns": ["192.0.2.1"]},
  "pending": null
}
```

- `config` is what is written in `20-wired.network`; `current` is what the system uses now.
- `mode`: `dhcp | static`. For `static`, `address` (IPv4), `prefixLength` (8–30) and `gateway` (IPv4 in the same subnet) are set.
- `dns`: up to 3 IPv4/IPv6 addresses. `useDhcpDns` applies only to `dhcp` (false = only `dns` is used).
- `pending`: `null` or `{"deadline": "<RFC 3339>", "previous": <config>, "next": <config>}` while a change waits for confirmation.

### `PUT /settings/network`
Body: a `config` object as above. Validates (address not network/broadcast/loopback/multicast/link-local,
gateway inside the subnet and different from the address, at least one DNS server for `static`),
applies it and returns `202` with the same shape as `GET` (`pending` set, deadline now + 180 s).
`409 change_pending` when another change waits. The UI then has to reach the NAS at the new
address, log in again (cookies are per host) and confirm.

### `POST /settings/network/confirm`
`200` with the `GET` shape (`pending: null`). `409 nothing_pending` when there is nothing to confirm
(e.g. it was already rolled back).

### `GET /settings/time`

```json
{"ntpServers": ["0.debian.pool.ntp.org"], "defaultServers": true,
 "synchronized": true, "serverName": "0.debian.pool.ntp.org", "serverAddress": "192.0.2.1",
 "timezone": "Europe/Prague", "now": "2026-11-25T16:00:00Z"}
```

- `defaultServers: true` when no own servers are configured (`ntpServers` then lists the distribution defaults).

### `PUT /settings/time`
Body `{"ntpServers": ["tik.cesnet.cz", "192.0.2.1"]}`: 0–4 entries, each a host name (RFC 1123, ≤ 253 chars)
or an IP address; empty list = back to defaults. Restarts timesyncd, returns `200` with the `GET` shape.

### `GET /settings/tls`

```json
{"subject": "CN=nas", "issuer": "CN=nas", "selfSigned": true,
 "dnsNames": ["nas"], "ipAddresses": ["192.0.2.51"],
 "notBefore": "...", "notAfter": "...", "sha256": "AB:CD:...", "keyType": "ECDSA P-256"}
```

### `PUT /settings/tls`
Body `{"certificate": "<PEM, leaf first, optional chain>", "privateKey": "<PEM>"}`, ≤ 64 KiB.
Checks that the key matches, the leaf is currently valid and the key is RSA ≥ 2048, ECDSA P-256/P-384 or Ed25519.
Stored in the state directory (key 0600) and used for new connections immediately. `200` with the `GET` shape.

### `POST /settings/tls/generate`
Creates a new self-signed certificate (ECDSA P-256, 825 days) for the host name and current IPv4 addresses. `200` with the `GET` shape.
