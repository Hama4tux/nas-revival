# Administration API v1

Status: implemented as a read-only prototype (M4), 2026-11-25. Served by the `nas-revival`
Go binary together with the static UI. All paths are below `/api/v1`. JSON only, UTF-8.

## Conventions

- Authentication: session cookie `nr_session` (`HttpOnly`, `Secure`, `SameSite=Strict`, path `/`),
  idle timeout 30 min, absolute 12 h. Every endpoint except `POST /session` needs it; otherwise `401`.
- CSRF: every non-GET request must carry `X-Requested-With: nas-revival`; otherwise `403`.
- Errors: `{"error": {"code": "<machine_code>", "message": "<human text>"}}`. No stack traces.
- Missing data is `null`, never `0`. Byte values are integers in bytes, temperatures in milli-°C.
- Timestamps are RFC 3339 UTC strings.

## Endpoints

### `POST /session`
Body `{"username": "admin", "password": "..."}`. `204` + cookie on success, `401 invalid_credentials`,
`429 rate_limited` (5 failed attempts per client IP within 5 min; `Retry-After` header in seconds).

### `GET /session`
`200 {"username": "admin", "expiresAt": "2026-11-25T18:00:00Z"}` or `401`.

### `DELETE /session`
`204`, cookie cleared.

### `GET /overview`
Poll every 5 s while the page is visible.

```json
{
  "generatedAt": "2026-11-25T16:00:00Z",
  "host": {"hostname": "nas", "os": "Debian GNU/Linux 13 (trixie)", "kernel": "6.12.119",
           "uptimeSeconds": 12345, "boardModel": "ZyXEL NSA310"},
  "cpu": {"model": "Feroceon 88FR131 rev 1 (v5l)", "cores": 1,
          "load1": 0.12, "load5": 0.10, "load15": 0.05, "usagePercent": 3.5},
  "memory": {"totalBytes": 262144000, "availableBytes": 180000000,
             "swapTotalBytes": 1073741824, "swapFreeBytes": 1073741824},
  "sensors": {"status": "ok",
              "temperatures": [{"id": "lm85/temp1", "label": "temp1", "milliCelsius": 41000}],
              "fans": [{"id": "lm85/fan1", "label": "fan1", "rpm": 1800}]},
  "network": [{"name": "eth0", "up": true, "speedMbps": 1000,
               "rxBytes": 123, "txBytes": 456, "addresses": ["192.0.2.10/24"]}],
  "storage": {
    "disks": [{"name": "sda", "model": "ST1000LM014", "sizeBytes": 1000204886016,
               "rotational": true, "removable": false}],
    "filesystems": [{"mount": "/srv/data", "device": "/dev/sda3", "fsType": "ext4",
                     "totalBytes": 1, "usedBytes": 1, "availableBytes": 1}]
  },
  "services": [{"name": "ssh.service", "label": "SSH", "state": "active", "since": "2026-11-25T15:10:00Z"}]
}
```

- `cpu.usagePercent` is `null` on the first sample after start (needs two `/proc/stat` samples).
- `sensors.status`: `ok | unknown | unsupported | fault`. Sensors come from hwmon, matched by driver
  name, never by a fixed hwmon index. A board profile (by device-tree model) may list the wired
  fans; then only those are reported, with a friendly label (NSA310: one fan, `lm85/fan1`).
- `network[].speedMbps` is `null` when the link is down or unknown.
- `filesystems` lists only real block-device mounts (no tmpfs/proc/cgroup).
- `services[].state`: `active | inactive | failed | done | unknown`; only an allowlist of units is reported.
  `done` is a oneshot unit that ran and exited successfully (e.g. LED setup at boot).
- `services[].since`: when the unit last changed its active state (systemd `StateChangeTimestamp`), or `null`.
  The UI derives "Poslední události" from it plus the boot time (`generatedAt − uptimeSeconds`).
- `filesystems[].device`: the kernel alias `/dev/root` is resolved to the real partition (via mountinfo and
  `/sys/dev/block`), so volumes can be matched to disks.

### `GET /smart`
SMART summary; cached for 10 min, disks in standby are not woken (`smartctl -n standby`).

```json
{
  "checkedAt": "2026-11-25T16:00:00Z",
  "disks": [{"name": "sda", "model": "ST1000LM014", "health": "passed",
             "temperatureCelsius": 38, "powerOnHours": 1200,
             "reallocatedSectors": 0, "pendingSectors": 0, "standby": false}]
}
```

- `health`: `passed | failed | unknown`. `standby: true` means values were not read.
- If `smartctl` is unavailable the response is `200` with `"disks": []` and `"error": "smartctl_unavailable"`.

## Settings (write operations)

All write endpoints need the session and the CSRF header. Validation errors are
`400 {"error": {"code": "invalid", "message": "<Czech text>", "field": "<json field>"}}`.
The web process forwards network/time operations to the privileged helper (ADR 0003);
if the helper is not reachable: `503 helper_unavailable`.

### `GET /settings/network`

```json
{
  "interface": "enp1s0",
  "config": {"mode": "dhcp", "address": null, "prefixLength": null, "gateway": null,
             "dns": [], "useDhcpDns": true},
  "current": {"addresses": ["192.0.2.51/24"], "gateway": "192.0.2.1", "dns": ["192.0.2.1"]},
  "pending": null
}
```

- `config` is what is written in `20-wired.network`; `current` is what the system uses now.
- `mode`: `dhcp | static`. For `static`, `address` (IPv4), `prefixLength` (8–30) and `gateway` (IPv4 in the same subnet) are set.
- `dns`: up to 3 IPv4/IPv6 addresses. `useDhcpDns` applies only to `dhcp` (false = only `dns` is used).
- `pending`: `null` or `{"deadline": "<RFC 3339>", "previous": <config>, "next": <config>}` while a change waits for confirmation.

### `PUT /settings/network`
Body: a `config` object as above. Validates (address not network/broadcast/loopback/multicast/link-local,
gateway inside the subnet and different from the address, at least one DNS server for `static`),
applies it and returns `202` with the same shape as `GET` (`pending` set, deadline now + 180 s).
`409 change_pending` when another change waits. The UI then has to reach the NAS at the new
address, log in again (cookies are per host) and confirm.

### `POST /settings/network/confirm`
`200` with the `GET` shape (`pending: null`). `409 nothing_pending` when there is nothing to confirm
(e.g. it was already rolled back).

### `GET /settings/time`

```json
{"ntpServers": ["0.debian.pool.ntp.org"], "defaultServers": true,
 "synchronized": true, "serverName": "0.debian.pool.ntp.org", "serverAddress": "192.0.2.1",
 "timezone": "Europe/Prague", "now": "2026-11-25T16:00:00Z"}
```

- `defaultServers: true` when no own servers are configured (`ntpServers` then lists the distribution defaults).

### `PUT /settings/time`
Body `{"ntpServers": ["tik.cesnet.cz", "192.0.2.1"]}`: 0–4 entries, each a host name (RFC 1123, ≤ 253 chars)
or an IP address; empty list = back to defaults. Restarts timesyncd, returns `200` with the `GET` shape.

### `GET /settings/tls`

```json
{"subject": "CN=nas", "issuer": "CN=nas", "selfSigned": true,
 "dnsNames": ["nas"], "ipAddresses": ["192.0.2.51"],
 "notBefore": "...", "notAfter": "...", "sha256": "AB:CD:...", "keyType": "ECDSA P-256"}
```

### `PUT /settings/tls`
Body `{"certificate": "<PEM, leaf first, optional chain>", "privateKey": "<PEM>"}`, ≤ 64 KiB.
Checks that the key matches, the leaf is currently valid and the key is RSA ≥ 2048, ECDSA P-256/P-384 or Ed25519.
Stored in the state directory (key 0600) and used for new connections immediately. `200` with the `GET` shape.

### `POST /settings/tls/generate`
Creates a new self-signed certificate (ECDSA P-256, 825 days) for the host name and current IPv4 addresses. `200` with the `GET` shape.
